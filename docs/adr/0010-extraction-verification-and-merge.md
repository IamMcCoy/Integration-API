# ADR-0010: 엔드포인트도 근거를 대조하고, 같은 API 의 조각은 적재 전에 합친다

- **상태:** Accepted
- **날짜:** 2026-08-06

## 배경

[ADR-0007](0007-evidence-based-confidence-scoring.md) 에서 "파라미터마다 딸려 온
evidence 가 원문에 실재하는지 대조한다" 로 채점을 정했다. 추출을 실제로 돌려 보니
그 채점에 구멍이 있었고, 앞뒤 단계에도 문제가 있었다.

정답은 문서에서 기계적으로 뽑았다 — `POST http(s)://[serverip]/mfd/api/token` 형태의
메서드+경로는 API 마다 고유하다. SECUI MFD 에서 24개.
→ [실험](../experiments/2026-08-06-extraction-quality.md)

**세 수정 전 상태: 3회 돌려 모두 적중한 API 가 13/24(54%), 파라미터 편차 36개(32%).**

## 선택지

문제가 넷이라 각각 갈렸다.

**1. 엔드포인트가 채점되지 않는다.** `Parameter` 에는 `evidence` 가 있지만
`ApiSpec.endpoint` 에는 없다. 모델이 `/acl/view`, `/api/protectDomain` 같은 경로를
지어내도 파라미터 근거만 맞으면 100점으로 자동 적재된다. 실측에서 환각 13개를 확인했다.

- A. `ApiSpec.endpoint` 에도 `evidence` 필드를 추가한다 — 스키마가 커지고 모델이 채워야 할 게 는다
- B. 채점할 때 엔드포인트 경로가 원문에 있는지 직접 본다 — 스키마 변경 없음

**2. 파라미터 없는 API 를 놓친다.** `PUT .../apply` 처럼 인자 없는 액션 API 가 문서에
있고 `Path parameters None` 이라고 명시돼 있는데, 프롬프트와 채점 양쪽이 "파라미터가
없으면 규격이 아니다" 로 처리했다.

**3. 한 API 가 여러 청크로 쪼개진다.** API 단위 1,213개 중 380개(31%). `api_schema` 는
`UNIQUE(api_def_id)` 라 나중 추출이 앞의 것을 덮어써 파라미터가 사라진다.

- A. `chunk_size` 를 키워 안 쪼개지게 한다
- B. 추출 전에 같은 API 의 청크를 이어 붙여 한 번에 넘긴다
- C. 적재 직전에 조각들을 합친다

**4. 추출이 실행마다 흔들린다.** 3회에서 적중 17~21, 파라미터 112~148.

## 결정

**1 → B.** `SpecScorer.score` 가 엔드포인트 경로를 원문과 대조하고, 없으면 **0점**을 준다.
스키마를 늘리지 않고 이미 있는 정보만으로 검증된다. 파라미터 오류는 인자 하나가 틀리는
것이지만 엔드포인트 오류는 호출 자체가 불가능하므로, 부분 감점이 아니라 통째로 버린다.

`'None'` / `'null'` 같은 문자열도 여기서 걸러 `endpoint` 컬럼에 안 들어가게 했다.

**2.** 프롬프트에 "파라미터가 없는 API 도 규격이다" 를 넣고, 채점은 엔드포인트에 근거가
있으면 100점을 준다. ADR-0007 의 "파라미터가 없으면 0점" 을 뒤집는다 — 근거가
**아무것도** 없을 때만 0점이다.

**3 → C.** A(`chunk_size` 키우기)는 실측으로 기각됐다. 청킹 지표는 전부 좋아지는데
**추출이 무너진다** — 8,000 에서 적중이 19 → 13, 파라미터가 198 → 63 이 됐다. 큰 청크에
API 가 여러 개 들어가면 모델이 일부만 뽑는다. B(묶어서 추출)도 같은 이유로 위험하다.

쪼개진 조각에서 각각 뽑아 **합치는 쪽이 더 많이 얻는다**(198 vs 63). 그래서 C 다.

병합 키는 **청크의 헤더 경로**다. LLM 이 낸 `title` 은 같은 API 라도 조각마다
`ACL 추가` / `ACL 추가 응답` 처럼 달라지지만, 헤더 경로는 문서 구조에서 오므로 일치한다.

그룹 안에서 **근거 있는 엔드포인트별로 한 번 더 나눈다.** 문서가 `5.2.4 적용/취소` 처럼
한 헤더에 API 둘을 묶어 쓰는 경우가 있어서, 그룹당 엔드포인트를 하나만 고르면 나머지를
잃는다(첫 시도에서 실제로 2개를 잃었다).

**4.** `temperature=0`. 재현성만 오를 줄 알았는데 정확도도 같이 올랐다 — 무작위성이
정답을 만들어내는 게 아니라 정답에서 이탈시키고 있었다.

**`chunk_size` 는 1,000 을 유지한다.** 500 은 오검이 44개로 폭증하고 2,000 부터
적중이 떨어진다. 1,000~1,500 이 최적 구간이다.

## 결과

**좋아진 것**

| | 전 | 후 |
|---|---|---|
| 3회 모두 적중 | 13/24 (54%) | **22/24 (92%)** |
| 파라미터 편차 | 36 | **9** |
| 적재 파라미터 | 112~148 | **147~156** |
| 환각 엔드포인트 | 자동 적재됨 | **13개 차단** |
| 반려(병합 효과) | 16 | 6 |

- 같은 입력에 같은 결과가 나온다. 3회 중 두 번은 완전히 동일했다.
- 엔드포인트 채점이 병합의 축으로도 재사용된다 — 환각 경로로 그룹을 쪼개지 않는다.

**나빠진 것 / 감수하기로 한 것**

- **ADR-0007 의 "파라미터가 없으면 0점" 을 뒤집었다.** 엔드포인트에 근거만 있으면
  파라미터 0개라도 100점이다. 실속 없는 규격이 자동 적재될 수 있지만, 문서에 실재하는
  액션 API 를 놓치는 것보다 낫다고 판단했다.
- **`api_extraction.source_text` 가 조각들을 이어 붙인 것이 됐다.** 청크 하나가 아니라
  묶음 전체라 길어진다. 승인 화면에서 파라미터마다 근거를 대조하려면 그 조각이 다 있어야 한다.
- **병합에서 엔드포인트를 못 찾은 조각은 단독으로 남는다.** 어디 붙일지 알 수 없어서인데,
  그 조각의 파라미터는 결국 어느 API 에도 귀속되지 않는다.
- **`temperature=0` 은 gpt-5 계열에서 에러가 난다.** 그 모델들은 이 인자를 받지 않는다.
  모델을 바꾸면 여기서 터진다 — 코드에 주석으로 표시했다.
- **완전히 결정적이지는 않다.** 3회 중 한 번은 적중 22, 파라미터 156 으로 갈렸다.
  편차가 9개로 줄었을 뿐이다.
- **문서 하나로만 쟀다.** SECUI MFD(39청크, 정답 24개). 표가 0개인 FortiOS 처럼 형식이
  다른 문서에서 같은 결론이 나오는지는 확인하지 않았다.
- `PUT /mfd/api/policy/pdomains/{id}` 하나는 3회 모두 90점을 못 넘어 승인 대기로 간다
  (87점, 파라미터 15개 중 13개만 근거 확인). 놓친 게 아니라 설계대로 동작한 것이다 —
  실험의 '적중' 집계가 `score >= 90` 만 세서 결함처럼 보였다.

**되돌려야 할 신호**

- 병합 때문에 남의 파라미터가 섞이면 — 헤더 경로가 아니라 엔드포인트만으로 묶는다.
- 엔드포인트 채점이 정당한 추출을 너무 많이 0점 처리하면 — 문서가 URL 을 본문과 다른
  형식으로 쓰는 경우다. 그때는 감점으로 바꾼다.
- 파라미터 없는 규격이 검토 대기열을 메우면 — 100점 대신 임계값 사이 점수를 줘서
  사람이 보게 한다.

## 후속

이 병합이 DB 앞에서 되돌려지고 있었다. `api_definition` 의 유니크 키가 `title` 이라,
엔드포인트별로 갈라놓은 apply/cancel 이 같은 행으로 다시 뭉개졌다.
실측 승인 25건이 정의 18개로 줄어 있었다. → [ADR-0012](0012-api-identity-is-the-endpoint.md)

18개 문서 전체 실측(2026-08-10)에서 "단독으로 남는 조각"이 예상보다 더 나갔다 —
어느 API 에도 귀속되지 않을 뿐 아니라, **엔드포인트가 None 이면 대조 자체를 건너뛰어
파라미터 근거만으로 100점을 받아 자동 적재되고 있었다.** 공통 응답 포맷·부록 표
조각이 전체 적재의 10%를 차지했다. 결정 1 을 조인다: 근거 있는 엔드포인트가 **없어도**
0점이다. → [실험 기록](../experiments/2026-08-10-full-corpus-threshold-validation.md)
