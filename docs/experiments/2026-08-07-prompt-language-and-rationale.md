# 프롬프트를 압축할 때 이유 설명을 빼면 정확도가 떨어진다

- **날짜:** 2026-08-07
- **결론:** 추출 프롬프트를 영어로 바꾸되 **왜 그래야 하는지를 함께 준다.**
  적중 22~23 → 24/24, 파라미터 143~156 → 173, 토큰 −10%.
  선별 프롬프트는 손대지 않는다 — 같은 방식이 거기서는 이득이 없다.

## 배경

[ADR-0009](../adr/0009-filter-model-and-prompt.md) 에서 선별 프롬프트만 영어로 바꾸고
추출·식별은 한국어로 남겼다. "아직 실험하지 않은 단계라 검증한 것만 바꾼다" 는 이유였다.

추출 실험([ADR-0010](../adr/0010-extraction-verification-and-merge.md))을 마쳤으니 이제
바꿀 근거가 생겼다. 토큰 비중을 재보니 선별보다 훨씬 컸다.

| 프롬프트 | 글자 | 토큰 | 한 요청에서 차지하는 비중 |
|---|---|---|---|
| filter (영어) | 365 | 71 | 20% |
| **extract (한국어)** | 652 | **347** | **55%** |
| identify (한국어) | 118 | 68 | 20% |

청크 본문이 평균 281토큰이므로, 추출은 **프롬프트가 요청의 절반 이상**이다.

## 가설

1. 영어로 바꾸면 선별처럼 토큰이 줄고 정확도는 유지된다

## 방법

선별 결과(29청크)를 고정하고 추출 프롬프트만 갈아 끼운다. 정답은 문서에서 뽑은
메서드+경로 24개. 지표는 최종 적중 API 수와 적재 파라미터 수다 —
프롬프트 품질은 토큰이 아니라 **얼마나 온전히 뽑아내는가**로 재야 한다.

## 결과 1 — 1판 영어는 확실히 나빴다

| | 1회 | 2회 | 3회 | 평균 적중 |
|---|---|---|---|---|
| ko (원본) | 22 | 22 | 21 | 21.7 |
| en (1판) | 18 | 19 | 18 | 18.3 |

3회 모두 일관되게 낮았다. 비결정성이 아니다.

여기서 **"한국어 문서에는 한국어 지시가 맞다"** 고 결론 내릴 뻔했다. 그럴듯한 설명도
있었다 — `evidence` 는 한국어 원문을 글자 그대로 옮기는 일이니 지시 언어가 같아야
"옮긴다"가 "번역한다"로 흐르지 않는다는 것.

**틀린 결론이었다.** 비교 대상이 부실했을 뿐이다.

## 결과 2 — 변수는 언어가 아니라 이유 설명이었다

변형을 둘 더 만들었다.

- `ko-tight` — 한국어 원본에서 **이유 설명과 예시만** 걷어낸 것 (652자 → 389자)
- `en2` — 영어인데 대상이 한국어 문서임을 밝히고, `evidence` 가 원문과 문자 단위로
  대조된다는 **채점 방식을 알려준** 것

| 변형 | 글자 | 프롬프트 토큰 | 적중 | 파라미터 | 입력 토큰 |
|---|---|---|---|---|---|
| ko | 652 | 347 | 23/24 | 147 | 43,948 |
| **ko-tight** | 389 | 202 | **18/24** | 126 | 39,743 |
| en (1판) | 1,018 | 230 | **18/24** | 122 | 40,555 |
| **en2** | 875 | **196** | **23/24** | **157** | 39,569 |

**`ko-tight` 이 `en` 1판과 정확히 같은 18/24 로 떨어졌다.** 언어가 원인이라면 한국어
압축본은 안 떨어졌어야 한다. 둘의 공통점은 하나다 — **이유 설명과 예시를 걷어냈다.**

내가 `ko-tight` 에서 지운 것들이다.

```
- 경로가 틀리면 그 API 는 호출 자체가 불가능하다      (왜 짐작하면 안 되는지)
- 적용/취소 같은 액션 API 가 그렇다                   (파라미터 없는 API 의 예)
- 'Path parameters None' 처럼 적혀 있으면            (문서에 실제로 나오는 표현)
```

`en2` 는 반대로 원본에 **없던** 이유를 하나 더 줬다.

```
this value is matched against the source text character by character,
and a reworded line is discarded
```

모델에게 채점 방식을 알려준 셈이다. 그래서 한국어 원본보다도 파라미터를 10개 더 뽑았다
(157 vs 147).

3회 대조에서도 `en2` 가 더 안정적이었다.

```
ko    적중 23 / 23 / 22    파라미터 147 / 147 / 143
en2   적중 23 / 23 / 23    파라미터 157 / 150 / 150
```

반영 후 본 코드로 돌리니 **적중 24/24, 파라미터 173** 이 나왔다. 지금까지 최고다.

## 결과 3 — 같은 방식이 선별에는 통하지 않는다

선별 프롬프트에도 같은 처방을 해봤다. 대상 언어를 밝히고, 목차 판별 힌트(`점선 뒤
쪽번호`)를 주고, 두 오류의 대가가 왜 다른지 이유를 붙였다.

파이프라인 끝까지 돌려 쟀다 — 선별 정답 라벨이 10개(참 2개)뿐이라 그것만으로는 약하고,
선별이 좋아지면 최종 적중이 올라가기 때문이다.

| 변형 | 토큰 | 선별 | 적중 | 파라미터 | 선별 입력 토큰 |
|---|---|---|---|---|---|
| current | 71 | 29 | 22, 23 | 144, 148 | 17,929 |
| v2 | 126 | 30 | 22, 22 | 143, 144 | 20,074 (**+12%**) |

**이득이 없다.** 적중은 동등하거나 낮고 토큰만 12% 늘었다.

지시의 복잡도 차이로 보인다. 추출은 규칙이 여덟 개고 그중 하나(`evidence` 를 글자
그대로)가 지키기 어려운 요구라 이유를 주면 준수율이 오른다. 선별은 참/거짓 하나이고
이미 재현율 100% 라 **설명을 늘려도 개선할 여지가 없다.**

선별 프롬프트는 이번이 네 번째 도전이다. ADR-0009 에서 "애매하면 참"은 무효였고,
`signal-based` 는 정밀도가 떨어졌고, 거짓 목록을 뺀 `positive-only` 는 20%로 무너졌다.
매번 현재 버전이 이겼다.

## 결론

- 추출 프롬프트를 `en2` 로 교체. 토큰 −10%, 적중·파라미터 개선.
- 선별·식별 프롬프트는 그대로.
- **압축할 때 이유 설명과 예시를 걷어내지 말 것.** 그게 이 실험의 실질적 수확이다.

→ [ADR-0011](../adr/0011-prompt-rationale.md)

## 남은 것

식별(`identify`) 프롬프트는 재지 않았다. 문서당 한 번뿐이라 토큰 영향이 미미하다.

문서 하나(SECUI MFD)로만 쟀다. 영어 프롬프트가 한국어 문서에서 이만큼 나온다는 건
확인했지만, 영문 문서(FortiOS 등)에서 한국어 프롬프트가 어떤지는 모른다.

## 재현

```bash
PYTHONPATH=. poetry run python scripts/2026-08-07-prompt-variants.py \
    '/tmp/mdcache/[SECUI] MFD REST API 가이드.md' [extract|filter]
```

`extract` 는 선별 결과를 고정하고 추출 프롬프트만 바꿔 가며 재고, `filter` 는 선별
프롬프트를 바꿔 파이프라인 끝까지 돌린다. 현재 프롬프트는 `conf/ia-conf.xml` 에서
읽으므로 설정을 고치면 그 값으로 비교된다.

검증 환경: `openai 2.53.0`, `gpt-4o-mini`, `temperature=0`, SECUI MFD 39청크.
